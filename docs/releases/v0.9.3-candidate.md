# MathQuest v0.9.3 candidate

23 September 2026. Starting main: `e7da71ba349cada401f0ec2f22deb4223d50d41d`. Implementation checkpoint: `5151161`. Branch: `release/v0.9.3`. This is a candidate, not a verified classroom release.

## Delivered changes

- Global MathQuest wordmark, MQ emblem and favicon; neutral setup, initial join, lookup failure and expired-session screens. New sessions require explicit cartridge selection.
- Registry-provided cartridge card, title, emblem, theme, stage labels and practice links. Unknown IDs produce neutral/unavailable presentation. Title/theme resets when returning to platform context. Valid Vault 7 stories, art, identifiers and saved keys remain intact.
- Ready alarm cars blink a localized red roof light slowly; active lights pulse more strongly for the existing twelve-second effect; spent indicators dim. Ordinary cars have no beacon. Reduced-motion preference produces a steady visible ready/active indicator. Rendering reads state without triggering audio, AI or charge consumption.
- Root practice/diagnostic entry pages now forward to canonical `public/` pages, preserving query and fragment. Corrected stale batch instructions that told the owner to overwrite repository-root files.
- Address migration inventory and an inactive proposed configuration profile. Repository and Netlify names and production URL settings are unchanged pending account preflight and cutover timing.

## Version and deployment compatibility

Front end/package: **0.9.3**. Compatible session engine and report schema: **0.9.2**. `BRAND.engineVersion` is checked by the front end and connection diagnostic. The existing v0.9.2 Worker requires no redeployment for UI/alarm rendering; Worker/storage protocol identity is deliberately unchanged. If an older Worker is installed, the batch file deploys the existing v0.9.2 engine. Always preserve current room/report evidence before an engine upgrade.

At existing addresses, Pages continues using the repository-root entry shims and `public/` source. Netlify continues proxying to the same Worker. No Netlify upload or naming change is needed to review this frontend candidate. See the repository README for the download/deployment sequence and `docs/migrations/v0.9.3-addresses.md` for the later migration.
